# Matched software-estimator / PMU comparison (spec §8.5.4)

This is an additional Phase-II validation experiment. It does not change the frozen Phase-I benchmark, thresholds, published results, or Hazel predictions.

`control.py` deploys to the eight ECE lab hosts, runs per-host smoke tests, runs full points, and retrieves archives. All benchmarks execute on ECE lab hosts, never on an HPC login node. `worker.py` uses the existing idle-core selection rule, waits when necessary, and records core changes. Full points contain one million single-load intervals, seed 5922026, random order, 8-byte spacing and footprints of 1 KiB, 1 MiB and 256 MiB. Native benchmark flags match Phase I. The full-stage revision skips LL event pairs that the smoke tests already showed unavailable.

The unchanged `cache_bench.c` binary is run first without an observer, then with L1D and LL event pairs where available. `region_pmu.c` is a separate Phase-II-only preload observer. It intercepts the benchmark's two `getrusage` calls to enable/disable per-thread user-mode hardware counters around the sampling loop. The observer does not classify timings or change the benchmark's source. Exactly two hooks, two counters, complete group reads and full scheduling are checked. Setup, warm-up and file output are excluded.

The timing-only calibration rule is unchanged: the midpoint between the unobserved hot P95 and cold P5, only when separated. No threshold uses PMU values. The same threshold classifies each observed run's raw intervals. Comparisons are recorded for all three footprints, with the 1 MiB workload consolidated in the report. Absolute error is in percentage points; relative error is 100 times absolute error divided by the hardware reference percentage. Relative error at a zero reference is undefined, not repaired. Invalid or unavailable PMU ratios are retained without an accuracy number.

**Interpretation:** counters cover all user loads in the timed region, including timer/loop/stack traffic. Thus their hit rate is not ground truth for just the pointer-chain loads. LL hits/accesses are conditional on reaching the LL event population; they are not an unconditional any-cache hit probability. Generic event semantics also vary by processor. Quantitative differences are comparisons against these named references, not proof of individual-load classification accuracy. Core changes, context switches, calibration sensitivity, block variability and differences from unobserved timing runs remain visible. There is one full acquisition per configuration, not independent repeated trials.

`hosts/*/raw-and-provenance.tar.gz` preserves all acquired full and smoke samples, logs, metadata, idle evidence and source snapshots. `analysis-<Slurm job>/` contains CSV/JSON comparisons, verified record summaries, raw archive hashes, calibration, report table and a comparison plot. Run `analyze.slurm` on Slurm; raw decompression, statistics and plotting must not run on a login node. Compiler errors or acquisition failures, if any, are retained rather than overwritten.

## Curated repository copy

Verified CSVs, calibration, summaries, comparison plot and verification are in `results/`. Full raw archives remain at the paths/hashes in `raw-archive-locations.json`; preserve or transfer them before scratch purge. No raw arrays, report files or compiled binaries are duplicated here. The C observer, frozen native benchmark and standard-library helpers are included as source. Original acquisition code and Slurm scripts preserve the original workspace paths; do not launch duplicate jobs into that original directory.

To reproduce analysis in this clone, restore each archive under `hosts/<host>/raw-and-provenance.tar.gz` and, from the repository root inside a Slurm job, run `PYTHONPATH=estimator_validation:$PYTHONPATH python3 estimator_validation/analyze.py` with Matplotlib available. The local `common.py` supplies the verified statistics implementation. Outputs go to a fresh `analysis-<job ID>/` directory. No ECE or Hazel benchmarks execute during analysis. New acquisition needs a fresh remote directory and the SSH/core settings reviewed for the current environment; `control.py` is the recorded original acquisition driver, not an instruction to rerun the frozen experiment.
